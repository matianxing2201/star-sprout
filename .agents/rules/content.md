# 内容规范 · 层级 / 契约 / 红线 / 流程

> 对应 `docs/standards.md` §3–§4 与 `docs/content-model.md`。加课、改内容模型前必读。

## 1. 内容层级

```
年级（星球）
 └── 领域 Category
      └── 主题 Topic
           └── 课程 Lesson
                └── 学习任务 Task
                     └── 互动 Interaction
                          └── 知识点 KnowledgePoint
```

- 一级分类固定八个且**顺序不可变**：中班 · 大班 · 一年级 … 六年级。
- **年级是星球，星球上的地方是学习世界。** 措辞不得混用。
- 没有课程的主题**不挡路**（不显示成「未解锁的死结」）。

## 2. 内容包契约

`src/content/schema.ts` 用 zod 定义全部结构，**每个 schema 都标注为 `z.ZodType<领域类型>`** ——
因此领域类型漂移在**编译期**暴露，而不是运行时。

入口：`parseContentPack` / `validateContentPack`。

`content.spec.ts` 额外守住：

- 所有引用（课程 → 知识点 / 互动 / 徽章 / 世界 / 地图）必须能解析，无悬空引用
- 八个年级齐全、顺序固定
- 领域 ↔ 主题**双向一致**（不能只有一边）
- 每节课六段式**首尾正确**（`intro` 开头、`reward` 结尾）
- `drag-drop` 的色彩**不得泄题**（答案不能靠颜色暗示）
- 所有互动的 `kind` 必须在册
- 徽章 / 世界 / 地图覆盖完整

## 3. 内容红线

| 红线 | 原因 |
| --- | --- |
| 不出现红叉 / ❌ / 「错误」字样 | 违反「错误不制造挫败」 |
| 不出现「暂无数据」 | 空状态要说人话：「还没有…，我们一起去找找」 |
| 不给幼儿设计机械抄写 | 路径是「图片 → 汉字 → 声音 → 游戏 → 记忆」 |
| 不把「幼小衔接」做成提前小学化 | 核心是习惯 + 兴趣 + 自我管理 |
| **不自行批量生成具体课程** | 具体内容由产品方提供教案 |

## 4. 六段式课程节奏（结构固定）

```
intro → discover → interaction → practice → challenge → reward
引入    知识发现    互动操作       练习       挑战        奖励
```

单个学习任务控制在 **1~3 分钟**；做对后**不自动跳走**，由孩子自己点「继续」掌握节奏。

## 5. 加一门课的标准流程

1. 在对应 `src/content/grades/<grade>/` 下按模板写内容
2. 需要新主题时同步 `taxonomy.ts` 与 `topics.ts`（双向一致，契约测试会拦）
3. 复用已有互动；确实需要新玩法才走 `interaction.md` 的 §4
4. `pnpm test` 让内容契约与 schema 校验过关
5. **不修改任何组件** —— 如果必须改组件，说明内容模型缺了表达能力，先补模型

> 模板见 `src/content/templates/lesson.template.ts`（参与类型检查，改它就是改契约）。

## 6. 学习记录是唯一事实来源

- 课程地图四状态、掌握度、薄弱知识点、成长总结全部是**从学习记录派生的值**，
  **不得各自维护一份**。
- 徽章规则是**声明式数据**（`BadgeRule`），不是散在各处的判断。
- **不惩罚**：连续学习中断不扣星星、不清等级、不出现负面文案。
- **徽章墙不隐藏未获得项**，显示「还差多少」—— 看得见的距离才是自驱力。
