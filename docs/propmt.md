# 儿童一站式自主学习 Web App

## 一、项目目标

我要开发一个面向儿童的“一站式知识学习 Web App”。

最终通过浏览器访问，主要使用鼠标点击、拖拽、选择、绘画、探索等方式完成学习。

目标不是制作传统的“课程列表 + 视频 + 题目”网站，而是打造一个：

> **生动、有趣、可探索、可互动、能让孩子主动想继续学习的儿童学习空间。**

核心目标：

- 提高儿童学习兴趣
- 降低学习枯燥感
- 培养自主选择和自主学习能力
- 通过游戏化交互增强知识记忆
- 让“学习”变成“探索和完成任务”
- 让孩子能够自己操作，而不是一直依赖家长
- 让不同年龄阶段的孩子进入适合自己的内容
- 后续可以持续增加课程和教案，而不需要修改前端整体结构

---

# 二、产品核心定位

不要设计成传统教育后台。

不要：

- 大量文字
- 密集课程列表
- 成人化 UI
- 大量表格
- 传统网课播放器
- “第1课、第2课、第3课”的机械结构
- 大量考试感
- 大量红叉/错误提示
- 复杂菜单

应该设计成：

> **儿童学习乐园 / 学习世界 / 探索地图**

孩子进入系统后，可以看到自己的学习世界。

例如：

- 📖 语言森林
- 🔢 数学城堡
- 🎨 艺术小镇
- 🔬 科学实验室
- 🌍 探索世界
- 🎵 音乐舞台
- 🧠 思维训练营
- 💻 编程空间

不同年龄进入不同的学习世界。

# 三、一级分类

系统一级分类固定为：

1. 中班
2. 大班
3. 一年级
4. 二年级
5. 三年级
6. 四年级
7. 五年级
8. 六年级

页面顶部或者首页应该能够非常直观地切换：

> 中班 → 大班 → 一年级 → 二年级 → 三年级 → 四年级 → 五年级 → 六年级

不要使用传统下拉框。

可以设计成：

- 年级星球
- 年级岛屿
- 成长阶梯
- 学习地图
- 年级卡片

让孩子能够理解：

> “我现在在哪个阶段？”

并且能够看到：

> “下一阶段会有什么？”

# 十五、儿童 Web 交互原则

这是整个项目最重要的部分。

## 1. 不要让孩子“看”

应该让孩子：

> 点击 → 操作 → 反馈 → 再操作 → 获得结果

---

## 2. 每一个知识点都尽量转成互动

例如学习：

> “大象比小兔子大”

不要直接展示文字。

可以：

- 出现大象和兔子
- 让孩子点击“大”
- 点击正确后大象放大
- 出现动画
- 角色说“答对啦！”

---

## 3. 让错误也有趣

不要：

> ❌ 回答错误

应该：

> “差一点点，再试一次！”

然后：

- 角色提示
- 局部动画
- 高亮关键区域
- 给出一次提示

让孩子不会因为失败产生挫败感。

---

# 十六、学习反馈机制

采用：

> 点击 → 反馈 → 状态强化 → 进度推进 → 奖励爆发

例如：

孩子完成一个任务：

1. 元素产生点击反馈
2. 正确答案出现动效
3. 角色做出反应
4. 进度条推进
5. 星星飞入收藏栏
6. 获得经验值
7. 解锁下一任务

整个过程控制在约 0.5～1.5 秒。

不要做成过于缓慢的教学软件。

---

# 十七、成长体系

不要简单使用：

> “完成课程 +1分”

应该建立儿童能够理解的成长体系。

例如：

### 星星

完成学习任务获得。

### 能量

连续学习获得。

### 徽章

完成特定挑战获得。

例如：

- 🌟 阅读小达人
- 🔢 数学探险家
- 🔬 小小科学家
- 🎨 创意大师
- 🎵 节奏达人
- 🧠 思维侦探
- 🚀 探索家

---

# 十八、学习地图

首页不要只是：

```text
语文
数学
英语
科学
```

而应该设计成一张儿童学习地图。

例如：

```text
                   ↑
        🔬 科学实验室
                   ↑

                   ↓
             📖 阅读森林
                   ↓
              🎵 音乐舞台
```

不同年龄看到不同地图。

# 十九、角色系统

建议建立固定 IP 角色。

例如：

- 🐻 熊老师
- 🐰 小兔
- 🐱 小猫
- 🦊 小狐狸
- 🐼 熊猫
- 🚀 小机器人

角色不是装饰。

角色需要承担：

- 教学
- 提问
- 提示
- 鼓励
- 错误反馈
- 奖励反馈
- 故事推进

让孩子形成：

> “我和角色一起学习”

而不是：

> “我在使用一个网站。”

# 二十二、课程时长

不要默认一个课程必须很长。

儿童课程应该拆成多个“小任务”。

例如：


> 1～3分钟

完成后可以自由继续。

# 二十三、自驱力设计

核心原则：

# 二十四、不要过度奖励

不要所有点击都：

### 正确

角色反馈 + 星星。

### 完成任务

奖励动画。

### 完成课程

较明显奖励。

### 完成章节

大奖励。

### 连续学习

特殊奖励。

# 二十五、家长模式

- 掌握知识
- 薄弱知识
- 连续学习

但不要把儿童端做成“考试排行榜”。

# 三十三、最终产品判断标准

完成第一版后，不要只检查：

> 页面有没有做出来。

而要检查：

### 儿童角度

- 我一眼能不能知道这里是什么？
- 我想不想点击？
- 我知道下一步做什么吗？
- 我能不能自己完成？
- 答错以后我还想不想继续？
- 完成以后有没有成就感？
- 有没有探索欲？

### 家长角度

- 内容是否系统？
- 是否符合年龄阶段？
- 是否能够看到学习进度？
- 是否知道孩子学了什么？
- 是否能够发现薄弱点？
- 是否感觉这是一个真正的学习产品，而不是小游戏集合？

### 产品角度

核心目标：

> **让孩子因为“好玩”进入，因为“探索”留下，因为“成长”持续学习。**

不要为了游戏化而游戏化。

所有动画、角色、奖励、地图和互动，都必须最终服务于：

> **理解知识 → 掌握知识 → 自主学习。**
